V1 — SEMANTIC SEARCH MVP
"ChatGPT for Media Navigation"
Timeline: Weeks 1–4

Mission
Build a production-grade, AI-native semantic media search system that transforms passive audio/video into a fully queryable knowledge base. The system accepts raw media, extracts meaning through transcription and embeddings, and returns precise timestamp-linked results in response to natural language queries — making every spoken word inside any media file instantly discoverable.

Full System Specification
Input Layer

Accept media upload in formats: .mp4, .mp3, .wav, .webm, .mkv, .m4a
Maximum file size: 2GB per upload
Support both local file upload and remote URL ingestion (YouTube links, HLS stream URLs, direct CDN links)
Validate media integrity before processing (ffprobe check)
Return upload ID and processing status immediately (async pipeline)

Transcription Layer

Use OpenAI Whisper (whisper-large-v3) as the primary transcription engine
Run Whisper locally via faster-whisper (CTranslate2 backend) for cost-zero operation
Output: full transcript with word-level timestamps (not just segment-level)
Handle multi-language detection; tag language metadata per segment
Post-process with punctuation restoration (deepmultilingualpunctuation or similar)
Store raw Whisper JSON output alongside cleaned transcript

Chunking Layer

Do NOT chunk by fixed token count alone
Use semantic chunking: split on topic shifts detected via sliding-window embedding similarity (cosine distance drop threshold)
Chunk size target: 120–250 words per chunk (tunable)
Each chunk must carry:

chunk_id
start_timestamp (seconds, float)
end_timestamp (seconds, float)
text (raw transcript text)
word_count
language
media_id (foreign key)


Overlap strategy: 1–2 sentence overlap between adjacent chunks to preserve contextual continuity

Embedding Layer

Primary: text-embedding-3-small (OpenAI) or nomic-embed-text (local, via Ollama)
Fallback: sentence-transformers/all-MiniLM-L6-v2 for fully offline operation
Embed every chunk independently
Store embedding vectors alongside chunk metadata
Batch embed in groups of 100 for efficiency
Normalize all vectors before storage (L2 norm)

Vector Storage Layer

Primary: ChromaDB (local, zero-infra) for MVP
Secondary: pgvector (PostgreSQL extension) for production path
Collection schema:

  collection: media_chunks
  fields: chunk_id, media_id, start_ts, end_ts, text, embedding[1536]

Support metadata filtering: filter search by media_id, language, time_range
Index type: HNSW (approximate nearest neighbor, M=16, ef_construction=200)

Search & Retrieval Layer

Query flow: natural language query → embed query → cosine similarity search → top-K results
Default K: 5 results (configurable 1–20)
Each result returns:

chunk_id
score (cosine similarity, 0–1)
start_timestamp
end_timestamp
transcript_snippet (full chunk text)
context_window (±1 chunk text for surrounding context)


Implement MMR (Maximal Marginal Relevance) re-ranking to avoid returning near-duplicate moments
Add keyword fallback (BM25) for when semantic search confidence is low (score < 0.4)
Hybrid retrieval: weighted blend of semantic (0.7) + BM25 (0.3) scores

Backend API Layer

Framework: FastAPI (Python) — async, typed, auto-docs at /docs
Endpoints:

Frontend Layer

Framework: React 18 + TypeScript + Vite
State management: Zustand (lightweight, no Redux overhead)
UI components: Radix UI primitives + custom CSS (no heavy UI libs)
Media player: Video.js with custom semantic overlay plugin

Non-Functional Requirements

End-to-end pipeline for a 60-minute podcast: under 4 minutes on CPU (Whisper base model), under 90 seconds on GPU
Search query response time: under 300ms (p95)
System should run entirely locally with zero API keys (using local Whisper + local embeddings)
Containerized: full docker-compose.yml for one-command startup
All pipeline stages independently restartable (idempotent operations)


Success Criteria

 Upload a 60-minute lecture → search "gradient descent" → returns 3–5 precise moments with correct timestamps
 Click a search result → player jumps to exact spoken moment
 Transcript panel scrolls in sync with playback
 System runs fully offline (no paid API required)
 Processing completes without manual intervention
